# AI Observability Guide

## Overview

The FoodHub AI Platform emits structured events through the execution path that enable full traceability of every AI request, from Admin question to structured insight.

## Correlation IDs

Every AI execution has three correlation identifiers:

| ID | Scope | Generated By |
|----|-------|-------------|
| `requestId` | Single HTTP request | `AIController` — `crypto.randomUUID()` |
| `traceId` | Full AI execution trace | `AIController` — `crypto.randomUUID()` |
| `conversationId` | Multi-turn conversation | Client-provided or `crypto.randomUUID()` |
| `toolCallId` | Single MCP tool invocation | `AIAgent` — `crypto.randomUUID()` |

## Frontend DCF Logger Integration

The Admin AI UI uses the existing DCF Logger (`@/core/dev/logger`) for client-side events:

```typescript
// Request start
logger.info('AI', 'User asked question', { 
  event: 'ai:request:start', 
  data: { question: userText } 
});

// Response complete
logger.info('AI', 'AI responded', { 
  event: 'ai:response:complete', 
  data: { toolCount: response.toolCalls?.length } 
});

// Error
logger.error('AI', 'AI request failed', { 
  event: 'ai:request:error', 
  error: err 
});
```

These events appear in the LogConsole (floating dev console) and are filterable by category `AI`.

## Traceability Reconstruction

To reconstruct a full execution trace:
1. Find all events with matching `requestId`
2. Events will span from `ai:request:start` to `ai:response:complete`
3. Use `toolCallId` to correlate tool start/complete/error pairs
4. Use `conversationId` to group multiple requests in a conversation

## Security — Never Log

The `AILogger` explicitly excludes:
- API keys (`AI_API_KEY`)
- JWT tokens
- Passwords
- Full request/response payloads (only metadata is logged)
- Stack traces in production events (only safe error messages)
- User PII (only userId for correlation)
